## The half-stop playback report

**Test (Verified).** On `GFI 12U 7P-5KL-3HS`, four stances were captured into the Progression Studio through the real click path (`HalfStopLeverButton._set_state`, then `MainWindow._capture_into_studio`): `P3_HALF + LKL` (split rule), `P1 + P2`, `P1_HALF + VL` (split rule) and `P3_HALF` alone (arpeggio style). They were played with the transport through a real `MidiAudioEngine(send=…)`.

**Result.** Every step replayed with the captured tokens on the canvas and the lever panel, and the MIDI note-ons matched the captured pitches exactly (for example strings 4-5-6 at fret 3 with `P3_HALF + LKL` → 68, 63, 59 on capture and on every loop). The stance also survives re-voice, a session round trip and a neck reload. The chain `StudioStep.controllers` → `stance_requested` → `apply_stance` → `set_active_controllers` → `FretboardResolver` is correct.

**What does lose a captured half-stop** — four real defects that produce the reported symptom:

1. **B1**: pressing Apply in the copedant editor silently deletes every captured stance on necks that still carry the legacy `VL` lever. This is the most likely cause.
2. **B3**: a step keeps its `_HALF` token after the half-stop rule is disabled, and then plays a default ±1 the UI says cannot be engaged.
3. **B13**: the voice-leading solver never produces half-stop stances, so any step that is re-voiced comes back with full stops only.
4. **B15**: playback re-strikes each step. The half-stop pitch is correct, but there is no glide into it, unlike a manual lever click.

If the bug is still seen after B1 and B3 are fixed, the exact neck and steps are needed to reproduce it.

### B4 — Pitch-bend range is assumed, never set · Read
- **Where:** `core/audio.py:119-124` (`BEND_RANGE_SEMITONES`, `cents_to_bend`), `:231-235` (`_init_channels`).
- **Problem:** all glides, half-stop swells and Newman cents assume the synth uses ±2 semitones. The engine never sends RPN 0, so any output device with a different range (many soft synths default to ±12 or ±48) scales every bend wrong: a 1-semitone half-stop glide lands 6 semitones away at ±12. Microsoft GS Wavetable happens to use ±2, which hides this.
- **Fix:** set the range explicitly. Using a wider range also removes the re-strike fallback for 3-semitone pulls (C6 P8, the `RKR + P1` compound raise) and allows bar-slide glides. At ±12 the resolution is 0.15 cent per step, which is still far below audible.

```python
# core/audio.py
BEND_RANGE_SEMITONES = 12.0

def _set_bend_range(self, ch: int, semitones: int) -> None:
    for cc, val in ((101, 0), (100, 0), (6, semitones), (38, 0), (101, 127), (100, 127)):
        self._send((0xB0 | ch) | (cc << 8) | (val << 16))

def _init_channels(self) -> None:
    for ch in ALL_CHANNELS:
        self._send(0x000019C0 | ch)
        self._send(0x007F40B0 | ch)
        self._set_bend_range(ch, int(BEND_RANGE_SEMITONES))
        self._bend(ch, 0)
```

  `cents_to_bend` and `glide_string_pitch` already read the constant. Update `05-persistence-and-audio.md` (it documents ±2).
- **Test:** the injected sink sees CC101/100/6 on every channel at start; a +3 semitone `glide_string_pitch` returns `True`.

**Glide and cents arithmetic, checked:** `cents_to_bend` scales by 8191 and truncates, so the worst error is about 0.05 cent at ±2 (and −200 cents maps to −8191, not −8192). The 16-step cosine ease ends exactly on the target because the last step uses `curve == 1.0`. Generation counters cancel superseded glides correctly. No audible precision defect was found apart from B4.

### B8 — JSON writes are not atomic and save failures are silent · Read
- **Where:** `core/models.py:552-555` (`SteelGuitar.save_to_file`), `core/profile_manager.py:154-162` (`save_profile`), `core/session.py:29-35`, `core/settings.py:50-56`, `ui/main_window.py:1593-1606`.
- **Problem:** every file is opened with `"w"` and written in place. A crash or power loss mid-write leaves a truncated file. For `active_guitar_setup.json`, `load_startup_guitar` then falls back to Factory without telling the user; for a user profile, the profile no longer opens. `_save_active_guitar_setup` writes two files and only logs errors, so a full disk or a read-only folder loses edits with no message. `switch_profile` calls it twice (four writes).
- **Race conditions:** none found. All file I/O is on the GUI thread, and the MIDI scheduler thread touches no files. Two app instances would overwrite each other's `active_guitar_setup.json` (last writer wins); that is not guarded.
- **Fix:**

```python
# core/storage.py (new, Qt-free)
import json, os, tempfile
from pathlib import Path

def atomic_write_json(path, payload) -> None:
    """Writes JSON to a temp file in the same folder, then replaces the target in one step."""
    path = Path(path)
    fd, tmp = tempfile.mkstemp(dir=path.parent, prefix=path.name, suffix=".tmp")
    try:
        with os.fdopen(fd, "w", encoding="utf-8") as f:
            json.dump(payload, f, indent=2)
            f.flush()
            os.fsync(f.fileno())
        os.replace(tmp, path)
    except BaseException:
        try:
            os.unlink(tmp)
        except OSError:
            pass
        raise
```

  Use it in the four writers. `list_user_profiles` globs `*.json`, so the `.tmp` suffix keeps temp files out of the list. In `_save_active_guitar_setup`, return a bool and show one status-bar warning on failure.
- **Also:** `sanitize_name` accepts Windows device names (`CON`, `NUL`, `COM1`…). On Windows 10, `CON.json` still opens the console device. Reject them in `_profile_path`.

### B10 — `ChordIdentifier` edge cases · Verified
- **Where:** `core/chord_identifier.py:67-118`.
- **Problems:**
  - **Family names are not `CHORD_FORMULAS` keys.** It returns `"Major 6"`, `"Minor 6"` and `"Dyad"`; the keys are `"Major 6th"` and `"Minor 6th"`. This breaks Critical Rule 18 and forces callers to translate or parse (A1).
  - **Enharmonic ties are decided by pitch-class number.** When the bass is not a root, candidates tie and the stable sort keeps the lowest root pitch class: `C-E-G-A` over E or G → `C6`, but `F-A-C-D` over A → `Dm7`; `A-C-E-F#` over E → `F#m7b5`, but `C-Eb-G-A` over G → `Cm6`. On a C6 neck, where 6 and m7 share every grip, the label flips with the key.
  - **Nothing beyond 4 notes:** `G-B-D-F-A` (G9) and `C-D-E-G-A` (C6/9) return `None`, although the formulas exist (E-08). `G-D-F` (7th without the 3rd) returns `None`.
- **Fix:** return real keys and break ties by the role of the bass note.

```python
_BASS_RANK = {0: 0, 3: 1, 4: 1, 7: 2, 6: 2, 8: 2}        # root, third, fifth; anything else = 3

def _rank(root_pc: int, bass_pc: int) -> int:
    return _BASS_RANK.get((bass_pc - root_pc) % 12, 3)

# candidates become (priority, bass_rank, tag, chord_type, root_name)
candidates.sort(key=lambda c: (-c[0], c[1]))
```

  With this, `C-E-G-A` over E or G is `C6` and `F-A-C-D` over A is `F6`: the same rule in every key. Replace `"Major 6"` / `"Minor 6"` with the `"…th"` keys, return `None` as the family for dyads, and update `_FAMILY_TO_CHORD_TYPE` in `relative_moves`. For 5-note chords, match generically against `CHORD_FORMULAS` (exact set, then "missing only the 5th") as `identify_grip_chord` in `core/progression_studio.py:391-422` already does; the two identifiers should share that code.
- **Test:** resolve the four grips above through `FretboardResolver` on the C6 preset and assert the family is a `CHORD_FORMULAS` key and stable across transpositions.

### B11 — Voicing search grips never use E9 strings 7 and 9 · Verified
- **Where:** `core/voicing_solver.py:44-48`.
- **Problem:** `STANDARD_E9_GRIPS` covers strings {1, 2, 3, 4, 5, 6, 8, 10} only. String 9 (D, the open b7) and string 7 (F#, the 9th) are the "chromatic" strings and appear in no grip, so the solver, the voice leader and the circle of fifths never propose the common `9-8-6-5` dominant or `7-6-5` add9 shapes. Extended chords are still found (E9: 349 voicings of E9, 625 of E13 up to fret 12) but only through pedals.
- **Fix:** add the standard chromatic grips (`[9, 8, 6, 5]`, `[9, 6, 5]`, `[9, 6, 5, 4]`, `[7, 6, 5]`, `[8, 7, 6, 5]`) and verify each with `grip_matches_chord` in a test, as Rule 8a requires. This changes the chord vocabulary, so re-run the preset tests.

### B12 — Other voice-leading edge cases · Read
- `fill_stances` (`core/progression_studio.py:345-382`) uses a pinned step only as the **start** fret of the next segment. The segment before a pin is not drawn toward it, so the bar can jump into a pinned step.
- With no `start_fret`, the DP uses `min_fret` as the target at 2000 per fret (`core/voice_leader.py:243-246`), so the first chord is always pushed to the lowest fret in range.
- The `"random"` trajectory calls the global `random` inside the DP loop (`:294-296`); results cannot be reproduced in tests. Pass an `rng`.
- A4 already covers the `.cp` rest and empty-progression faults.

### B13 — The solver has no half-stop stances; the Atlas does · Read
- **Where:** `core/voicing_solver.py:88-120` against `core/copedant_compare.py:331-339`.
- **Problem:** Chord Atlas and Compare add a `<ID>_HALF` variant for each controller with an active rule. `VoicingSolver` does not. The Studio's voice leading, the circle of fifths and the star map therefore never choose a half-stop, and a half-stop chord can only enter a progression by capture. This is why B1 is unrecoverable.
- **Fix:** move the half-stop variants into `VoicingSolver.candidate_stances(neck, include_half_stops=False)` and let `fill_stances` opt in. `ErgonomicsEngine` callers already strip `_HALF`.

## GUI and usability

### B14 — Lever buttons: 240 ms lag and an inverted gesture · Read
- **Where:** `ui/lever_panel.py:46-61`.
- **Problem:** every press starts a 240 ms timer to tell a single click from a double click, even on controllers with no half-stop. Every pedal toggle, and the swell glide that follows it, is a quarter of a second late. On controllers that have a half-stop, the common action (full engagement) needs a double click, and the half-stop is the single click.
- **Fix:** act at once when there is no half-stop.

```python
def mousePressEvent(self, event):
    if event.button() == Qt.LeftButton:
        if not self.has_half_stop:
            self._set_state(0 if self.state else 2)          # no delay
        elif self._single_click_timer.isActive():
            self._single_click_timer.stop()
            self._set_state(0 if self.state == 2 else 2)
        else:
            self._single_click_timer.start(240)
    super().mousePressEvent(event)
```

  Better still for half-stop controllers: left click = full, right click or Shift+click = half. No timer is needed and the cycle is explicit. Show a small "½" corner mark on buttons that have a half-stop; today nothing tells the user which ones do.

### B15 — Playback never glides · Read
- **Where:** `ui/main_window.py:712-724`, `:599-618`.
- **Problem:** a manual lever change bends ringing strings (`_swell_sounding_strings`), but the Studio re-strikes every step. Two steps at the same fret that differ by one pedal or a half-stop sound as two plucks, not as a pedal move, which is the sound a steel player expects.
- **Suggestion:** add a per-step style "Swell from previous": when the fret and grip are unchanged, call `glide_string_pitch` for each common string instead of `_play_pocket`. With B4 at ±12, bar slides between frets can glide too.

def _name(c: str) -> str:

### B17 — Custom widgets
**`ui/fretboard_canvas.py`**
- No keyboard control (`keyPressEvent` is absent; the whole `ui/` has one shortcut). Add Left/Right for the bar fret, 1–0 to toggle strings, Space to pluck, and `setFocusPolicy(Qt.StrongFocus)`.
- `setMinimumWidth(900)` (`:45`) plus `MainWindow.setMinimumWidth(1180)` (`ui/main_window.py:79`) makes the app unusable on a 1366 px laptop at 125 % scaling. With 24 frets across the minimum width, a fret cell is about 32 px. Offer a "frets shown" range (0–12, 0–15, 12–24) so up-the-neck work gets wider cells.
- Fonts are fixed `QFont("Segoe UI", 6…9)` (`:275-711`); 6 pt is hard to read on HiDPI and ignores the system font. Derive from `self.font()` and scale with the fret width.
- A half-stop and a split are flags on `ActiveStringState` (`is_half_stop`, `is_split_applied`). Draw them distinctly on the node (for example an amber ring for a half-stop, a split glyph for an override) so the user can see *why* a pitch differs from the plain sum.
- For up-the-neck chords, show ghost markers for the other positions of the current chord and grip (the Atlas' Find results) on the board, so the next position is one click away.

**`ui/star_map_widget.py`**
- The table shows raw controller IDs (`:130`); use `describe_controllers(lm.controllers, controller_display_names(neck))`.
- `_select_pocket` picks a landmark by substring of its display label (`"D" in l.label`, `:143-147`). That is logic on display text (Critical Rule 2 in spirit) and matches any label containing a "D". Give `StarMapLandmark` a kind field.
- The table is editable (no `setEditTriggers(NoEditTriggers)`), the engine is recomputed on each click (`:138`, `:152`), the dialog is modal so the fretboard cannot be played while it is open, and only major keys are offered.
- The pocket buttons have fixed E9 text ("A&B ⟷ D Lever") even on C6 necks.

**`ui/grip_pocket_bar.py`**
- A grip that loses a string on a smaller neck is trimmed but stays in its original size group (`:103-105`), so a 3-string chip can sit under "4-note".
- There is no way to save a custom pocket as a chip, and the chips show only string numbers. Show the grip's sounding chord for the current stance in the caption (`lbl_selected`), since that is what the player cares about.
- Chips have no keyboard access and no "previous / next grip" step, which is the usual move when walking a chord up the neck.

### B18 — Theme and layout · Read
- D-39 and D-40 stand. Root cause: nearly every widget sets an inline stylesheet with dark-mode hex colours (`lever_panel.py`, `grip_pocket_bar.py`, `star_map_widget.py`, `progression_studio_widget.py`), and `ThemeManager` rewrites them by regex at run time (`ui/themes.py:255-357`). That costs a pass over `allWidgets()` on each switch, and an event filter runs on every `StyleChange` and `Polish` in the app.
- **Direction:** move state colours to dynamic properties and style them once in the two app stylesheets.

```python
# widget
btn.setProperty("engagement", "half")       # "off" | "half" | "full"
btn.style().unpolish(btn); btn.style().polish(btn)
```

```css
/* DARK_THEME_QSS / LIGHT_THEME_QSS */
HalfStopLeverButton[engagement="half"] { background-color: #d39e00; color: #12151c; }
HalfStopLeverButton[engagement="full"][pedal="true"] { background-color: #0d6efd; color: #ffffff; }
```

  Each widget converted this way leaves the `ThemeManager` queue for good.
- Fixed pixel heights (`setFixedHeight(34)` on lever and action buttons, `24` on chips) with 11 px fonts clip when Windows text scaling is above 100 %. Use `setMinimumHeight` with font-metric-based values.
- Studio cards size as `70 + 16 * beats` px (`progression_studio_widget.py:418`), so a long chord symbol on a 1-beat step is cut off.
